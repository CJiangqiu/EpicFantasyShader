# 渲染结构与阴影原理

## 管线

`shadow` 从日月方向记录遮挡物深度。`prepare` 填充线性颜色背景，`gbuffers` 在绘制几何时计算光照并写入 `colortex0`，主世界不透明绘制后由 `deferred` 生成半分辨率体积云，`deferred1` 在完整分辨率合成，并向 `colortex5` 输出不透明场景与云的反射快照，透明物在 `colortex0` 中混合。`composite` 在透明深度完成后生成半分辨率水下阳光散射，`final` 合成水雾与散射，再处理亮度和显示编码。

主颜色缓冲采用 RGBA16F。只使用一个主颜色缓冲，不分配法线、材质或时域历史缓冲。光照为前向计算；不可见几何和透明叠层造成的额外片元成本需要游戏内测量。

地形接收原版环境遮蔽，方块光来自顶点光照坐标。天空、粒子和发光覆盖层具有独立入口，避免使用缺失或不适用的表面法线。三个维度共享程序，日月阴影仅在主世界启用。

## 阴影精度与边缘

阴影投影把更多纹素分配给相机附近。投影写入和接收端共用变换，深度压缩为光源方向的遮挡物预留空间。该变换不是级联阴影；大三角形与近地平线光线下的表现需要实际检查。

低、中、高质量分别进行 4、9、16 次硬件比较采样。每次采样对邻近深度进行比较并插值，固定采样位置及加权平均使边缘连续，不使用随帧变化的随机旋转，也不依赖时间累积。

过滤仅决定日月直射光的可见度。环境光和方块光独立计算，因此阴影下仍保留材质与色彩层次。阴影范围边缘渐隐，避免硬切线；范围以外的光照依赖天空光照近似，并不具备真实遮挡。

接收点沿法线做小幅偏移。过滤时利用屏幕导数求接收面在阴影图中的深度斜率，再为每个采样点修正比较深度。硬件双线性比较的四个纹素共享参考深度，因此还按纹素内位置补偿其中最浅的接收面深度。偏移过大依然可能造成接触阴影脱离。

`shadowtex1` 提供不透明遮挡。纹理透明度用于镂空裁剪，水和玻璃的材质分类用于排除不透明投影。这里没有彩色透射、遮挡物搜索或随距离扩展的半影计算。

## 星体与云开关

`clouds=off` 与 `dhClouds=off` 关闭原版及 DH 云。普通云入口额外丢弃片元，DH 通用入口仍用于非云对象。

圆月直接替换主世界天空纹理入口中的月亮绘制，复用原版月亮四边形，不额外叠加第二个月亮。切向缩放按视直径计算，并预留抗锯齿边缘范围；因此尺寸不受原版贴图中月面的大小限制。原版外观直接采样月相图集，保留资源包纹理。

月相使用 `moonPhase`，通过球面光照分界计算八种明暗形状。月面采样 `textures/moon.png` 正面圆盘图像，通过几何阶段的 `gaux1` 绑定并转入线性颜色空间。图片提供月海和环形山细节，不额外叠加球面边缘压暗。圆面及明暗分界使用屏幕导数抗锯齿，天气淡出沿用天空顶点透明度。

月面仅在月亮四边形中采样，使用双线性过滤及边缘夹取，没有全屏月面采样或额外渲染缓冲。月面纹理来自 klookiea 的 The Moon (No Background)，作品页面为 https://opengameart.org/content/the-moon-no-background ，标注 CC0 1.0；其月面输入素材来自 NASA/Goddard 的 CGI Moon Kit（https://svs.gsfc.nasa.gov/4720/）。月亮大小与亮度只控制外观，不改变日月方向光函数。月亮和普通天空几何先于前景绘制，沿用当前透明合成路径。

星点由 `lib/stars.glsl` 按固定世界方向生成，六个方向面各划分 24×24 个单元，默认约五分之一的单元包含星点，密度选项改变单元启用比例。星点中心在单元内随机偏移，角距离在单位球面计算，使轮廓保持圆形。半径与亮度分别变化，白色占多数，其余为低饱和的蓝白、暖黄和橙红；不对应真实星表，不模拟恒星每日周转。屏幕导数提供边缘抗锯齿与亚像素能量衰减，闪烁采用固定相位的平滑正弦亮度变化，幅度和速度可配置，不使用逐帧随机数。

星点在 `prepare` 背景与普通天空覆盖阶段共用同一方向重建及颜色函数，保留原版天空底色与晨昏几何。原版星点同时通过 `stars=false` 及天空入口的 `MC_RENDER_STAGE_STARS` 丢弃关闭。程序星点仅用于主世界，随太阳高度、降雨强度及地平线高度平滑淡出；普通几何在其后绘制以遮挡背景。每个片元只检查所属单元，不遍历整个星表；实际开销须在游戏中测量。

## 手持移动光源

主副手分别使用 `heldItemId`、`heldItemId2` 与对应的 `heldBlockLightValue`。`oldHandLight=false` 保持双手亮度独立；物品分类由 `item.properties` 提供，未分类发光方块使用加载器亮度及暖色回退。

两只手的光源近似位于相机下前方的同一位置，经视图逆矩阵变换到表面使用的坐标系。每个光源采用有限距离衰减、平滑范围边缘和法线朝向响应。两只手的照明相加，不增加纹理采样或额外渲染阶段。

该模型在第三人称中仍以相机为中心，不表示真实的手部世界坐标。它不计算墙体遮挡、独立点光源阴影或任意实体照明。掉落物不在双手接口的数据范围内，当前管线没有实体光源列表或收集阶段。

## DH 边界

DH 的地形、水与通用对象各有入口，保留顶点颜色、光照和透明度。通用对象不执行地形距离裁剪或地形透明度阈值。普通与 DH 表面使用相同的光照与雾函数。

DH 不透明程序不读取普通地形深度。DH 水在透明阶段使用已完成的普通不透明深度遮挡前景后方的水面。此实现没有双向深度交接、抖动过渡或透明层排序重建，不能据此宣称任意视距和模组组合均无接缝。

`dhShadow.enabled=false` 关闭远景投影。这样普通地形阴影图不接收简化地形，但远处山体也不会向普通地形投影。远景使用天空光照近似。

## 验证范围

- 结构检查验证入口配对、引用可解析性、中英文选项及三档预设的完整参数集合，防止切换预设遗漏效果开关。
- 本机编译覆盖三个维度、三档阴影、阴影关闭及 DH 宏开关，并链接所有不同的程序组合。加载器的着色器改写不在本机编译检查内。
- GPU 过滤回归直接引用运行时 GLSL，用人工深度图检查受光平面、不透明遮挡、不同斜率的接收面、边缘连续性和柔和度响应。
- 手持光源 GPU 回归检查双手光色、叠加、空手与移走光源、未知物品亮度回退、范围外熄灭、背光面、相机平移和关闭状态。
- 月亮 GPU 回归直接编译天空入口，以原版尺寸的人工四边形验证八种月相、角尺寸、亮度、天气透明度、太阳与维度隔离、原版外观，以及云片元丢弃；预览不代表游戏内天空画面。
- 离线预览展示人工深度图上的过滤结果，不包含游戏几何、加载器资源绑定或完整阴影投影。

游戏验收应覆盖晴天树叶投影、围栏等细小物体、斜坡、日出日落、室内外、月光、玻璃和水，以及 DH 开关、三个维度。检查条纹、悬浮、边缘跳动、漏光和透明遮挡，并记录同场景阴影开关与三档预设的帧时间。不能用离线预览替代这些验收。

## 流星

`lib/meteors.glsl` 用整数混合函数对 `worldDay` 抽签，比较 `METEOR_NIGHT_CHANCE`；默认阈值 0.15。日期不变时抽签结果不变，不依赖客户端重载。它不读取世界种子，相同游戏日期及配置具有相同流星夜结果，时间命令改变日期也会影响结果。主世界夜间及天空可见度共同限制显示，其他维度不调用该模块。

流星动画使用 `frameTimeCounter`，按可配置间隔划分时间段。每段内选定一个足以完成消退的起始时刻，普通流星最多同时显示一颗。该时钟可在暂停菜单继续计时，并按加载器规则循环；重载可能改变动画进度，但不改变当晚抽签结果。轨迹使用球面大圆运动，尾迹在球面计算角距离并随距离衰减，头部单独计算圆形高光。速度与尾长使用角度单位，持续时间、宽度、亮度和颜色独立配置。此效果没有实体交互、地表光照或独立阴影。

`tools/test_meteors.py` 使用运行时 GLSL 验证大量日期的抽签分布、0/1 概率边界、运动及消退、昼夜天气条件和外观参数响应；其预览为上半球展开图，具有投影畸变。`tools/test_stars.py` 在实际天空和背景入口验证星点及流星合成一致性、维度隔离与原版星点丢弃。离线验证不替代游戏内画面与性能验收。

接口依据：[世界日期与时间](https://shaders.properties/current/reference/uniforms/world/)、[运行时钟](https://shaders.properties/current/reference/uniforms/system/)。

流星雨使用与流星夜不同的整数种子再次抽签，只有流星夜成立且第二次随机值小于 `METEOR_SHOWER_CHANCE` 时启用。默认条件概率为 0.5，总概率约为 0.15×0.5=0.075。六条独立时间序列共用当晚的天空区域及运动方向。公共方向投影到各起点的球面切平面，朝向该区域中心观察时轨迹平行，起点与出现时刻独立变化；每条序列的间隔为普通间隔的五分之一，且不短于流星持续时间加 0.5 秒；单颗外观沿用普通流星参数。所有轨迹仍在背景阶段合成，普通流星路径仅计算一条序列。GPU 回归验证条件概率、非流星夜排除、概率边界、同日稳定性、密度差异及雨天和白天隐藏。

## 极光

`lib/aurora.glsl` 在天空两侧及头顶的三个区域分别构建三条同向舒展光带及一片局部短光幕。每个区域有独立坐标系与噪声种子，不随相机旋转移动。区域内部的主体以不同长度、倾斜和缓和弧线保持带状轮廓，细束向上延伸；短光幕单独使用有限范围的坐标弯曲与高低光柱，端部柔和淡出。黄绿色亮边向低亮度青绿色上缘过渡，光带间保留夜空空隙。它是天空方向上的程序化发光图案，不是体积积分或真实磁场模拟，不产生地表照明。极光与星点、流星共用几何之前的背景及天空覆盖入口，普通地形与 DH 几何在其后遮挡背景。

`auroraColdFactor` 通过自定义 uniform 表达式读取群系 `temperature`，以 0.15 为寒冷阈值，用 `smooth` 的独立编号 91 及双向 5.0 参数进行过渡。该判据使用群系基础温度，不代表海拔修正后的积雪条件。模组群系由其温度属性决定。主世界、寒冷权重、夜间及天气共同限制显示，白天和完全降雨时不执行光幕噪声计算。纹理资源不参与极光生成。

Oculus 1.8.0 以 ISO-8859-1 读取 `.properties`，预处理器按 Java `\R` 分行。UTF-8 中文可能包含 `0x85`，解码后成为换行符，使注释残片进入预处理器并中断后续配置读取。属性文件的中文说明放在对应 GLSL 或本文中；结构校验检查此字节。语言文件使用独立的翻译加载路径。

动画使用客户端运行时钟，因此可能在暂停菜单继续流动，加载器重载或时钟循环可能改变动画相位。土豆预设关闭极光，默认与极致开启；外观参数不随预设改变，实际帧时间须在游戏测量。`tools/test_aurora.py` 检查实际背景入口的寒冷权重响应、白天与雨天隐藏、地平线淡出、维度隔离、天空覆盖一致性、参数与动画连续性；离线检查未执行加载器自定义表达式，也不替代群系边界的游戏内验收。

接口依据：[自定义 uniform 与平滑表达式](https://shaders.properties/current/reference/shadersproperties/custom_uniforms/)。


## 绚丽星空与血月

`lib/fantasy_sky.glsl` 由背景和天空共用的夜空合成调用。总开关默认开启；开启后以球面三维噪声生成默认紫色的星云薄雾和尘埃空隙，无外部纹理资源。星云只向天空颜色添加发光，不是地表雾、体积云或真实天文模拟。

血月是普通月亮之外的单颗红褐色卫星，圆盘使用球面法线、程序岩质色斑、偏下侧照明及抗锯齿边界，受光面不足半圆，暗面不自发光且保留遮挡。它覆盖自身轮廓内的星点与星云，普通月亮继续由原有日月入口绘制。普通月亮与血月同属中层，重叠时普通月亮绘制在前；不模拟两者的真实距离。血月独立轨迹由世界时间驱动，默认视直径 24 度；使用固定美术光照，不声称真实轨道、月相或天文位置。

出现条件为 `worldDay` 对配置间隔取模等于间隔减一，默认 8 天；间隔 0 通过编译分支直接允许每晚显示，不执行取模。出现日期在存读档及光影重载之间保持一致，修改世界日期会相应改变事件。夜间可见性与天气限制共用星空函数，白天和完全降雨时跳过星云及卫星计算。效果不产生地表光源或生物事件。

`tools/test_fantasy_sky.py` 使用实际背景与天空入口检查总开关、独立子效果、日期周期、每晚模式、天气、维度隔离、大小、轨迹及卫星对背景的遮挡。`tools/test_moon.py` 检查绚丽星空开关不改变普通月亮和太阳。离线 GPU 图像用于美术预览，不代替游戏内视觉和性能验收。


星云子页保留独立开关与亮度，提供紫、蓝、玫红、金四色。浓度控制噪声到薄雾密度的阈值偏移，覆盖范围控制天空带宽，云团大小控制球面噪声尺度，细节强度混合低频噪声与多尺度纹理，尘埃强度控制暗纹；方位绕世界竖直轴旋转。速度默认 0，非零速度沿闭合轨迹缓慢移动噪声，整数速度与加载器 3600 秒时钟周期衔接。天空夜间及天气淡出仍由统一可见度函数控制，不影响地表雾色或血月表面。

星云参数回归检查四种配色、浓度与覆盖响应、云团尺度、细节、暗纹、方位、静止模式、逐帧流动和时钟循环连续性；`.artifacts/validation/nebula-preview.png` 为紫、蓝、玫红、金的离线对照，不包含地形与游戏后处理。


## 天空叠加层级

远层为星点与星云，中层为普通月亮与血月，近层为流星与极光。背景合成先应用血月遮挡，再调用共享的 `proceduralNearSky` 添加近层发光。圆月通过完整圆盘覆盖远层，月相只影响受光颜色；暗面使用天空底色，避免透出星点和星云。原版月亮模式保留资源纹理的透明轮廓。

普通月亮入口显式使用源透明度混合，在源颜色内加入同一近层发光。若远层为 B、月面为 M、近层为 F、覆盖率为 a，背景为 B+F，月面混合得到 a(M+F)+(1-a)(B+F)=aM+(1-a)B+F。这样月面、抗锯齿边缘和天气淡出均保留一份近层，不重复增亮，也不读取当前正在写入的颜色附件。

月面 GPU 回归使用已知前景颜色和实际混合状态，检查圆月及原版月亮、满月/半月/新月、天气透明度下的层级与能量。血月回归检查远层星空被遮挡且近层仍完整叠加。近层效果自身由极光与流星的独立回归验证；游戏中的交叉画面仍需视觉验收。


## 程序太阳

主世界的天空纹理入口通过日月方向区分太阳与月亮。圆形太阳默认视直径 5.3 度，顶点阶段从太阳四边形的局部 UV 与切向位置计算原有尺寸，再按视直径缩放并扩展光晕范围。光晕外缘归零，最大大小组合也不依赖原版纹理边界。原版模式保留资源纹理，圆形模式不采样太阳贴图。

`lib/sun.glsl` 使用圆盘覆盖率、轻微边缘亮度衰减和指数光晕；太阳高度连续混合暖白与晨昏橙色。天气透明度沿用天空顶点透明度，太阳外观参数不改变方向光或阴影。圆形太阳沿用天体中层合成方式，近层流星与极光保留在前景。

`tools/test_sun.py` 使用实际日月入口检查视直径、圆形轮廓、光晕开关及扩散、晨昏连续性、天气、纹理独立性、原版切换及月亮/维度隔离。`.artifacts/validation/sun-preview.png` 从左至右为日间、晨昏、无光晕和宽光晕。预览不代表游戏内天空配色，实际视觉与性能仍需游戏验收。


## 天空底色连续性

`lib/sky_background.glsl` 根据世界空间视线高度，将地平线的 `fogColor` 平滑混合到高处的 `skyColor`，在线性颜色空间计算。主世界的全屏 `prepare` 与天空几何的 SKY 阶段均使用相同函数和视线重建，不以原版天空盘的顶点颜色决定覆盖区的底色。地平线以下保持雾色；水下朝天空方向保留天空色、低处使用深水色；熔岩和细雪内使用加载器雾色。其他维度保留自己的背景路径，晨昏等非 SKY 绘制阶段保留顶点颜色。

圆月暗面采用同方向的天空底色，仍遮挡远处星点和星云。背景在几何之前绘制，保留地形、DH、水与玻璃的正常合成时机，不在最终阶段替换像素。

`tools/test_sky_background.py` 在实际背景与天空片元入口上传不同的雾色/天空色，检查局部几何覆盖、不同俯仰视角、晴天/阴天/夜晚配色、地平线连续性、介质内背景与维度隔离；测试不替代加载器内颜色上传时机及实际游戏画面的验收。

## 天气体积云

`lib/clouds.glsl` 定义世界空间的连续三维密度场；两层不同方向的低频噪声控制云区与空隙，连续三维噪声经坐标扭曲和多尺度组合构造不规则主体。云底较平缓，云顶随局部密度场起伏，细节侵蚀集中于薄云和轮廓；区域边界平滑衰减，密度在水平与垂直方向连续。群系云量与云体浓度分别控制。晴天云底默认 Y=320，厚度 256 格，降雨与雷暴连续增厚。天气调整覆盖阈值与消光强度，普通降雨时乌云覆盖大部分天空，雷暴通过连续的层状密度下限填合云团空隙；云底和云顶仍沿局部包络平滑过渡。雨天与雷暴分别压低日月散射、天空照明和云层远处的雾化亮度，雷暴呈更深暗的云幕。群系湿度和高原权重仅影响晴天基准。群系来自玩家所在位置，并经过自定义 uniform 平滑，不是远处每一块地形的独立气象模拟。

云噪声由 `tools/build_cloud_noise.py` 独立生成，`textures/cloud_noise.png` 通过共有的 `texture.noise` 接口绑定到 `noisetex`。图集为 657×657 RGBA8，按 RGBA8 存储约占 1.65 MiB；72³ 的周期格点按四通道打包相邻横坐标与高度切片，两次精确纹素读取即可取得一个三维单元的八个角点。GLSL 使用五次平滑权重显式插值，图集边界有重复行，负坐标与周期接缝保持连续。周期和八位格点精度属于噪声近似，不代表无限非重复噪声。云形、云内照明、普通地形与 DH 云影共用同一纹理和密度函数；空云区、垂直包络外及无需侵蚀的厚云跳过无贡献的细节计算。

接口已核对本地 Oculus 1.8.0 的配置解析与自定义 PNG 加载路径；其他加载器仍需分别验收。接口规范见 [OptiFine 官方配置文档](https://github.com/sp614x/optifine/blob/master/OptiFineDoc/doc/shaders.properties)中的 `texture.noise`。离线 GPU 工具绑定与发布包相同的纹理；纯编译检查不上传纹理。

`lib/cloud_render.glsl` 将视线与云层上下界求交，并以普通 `depthtex0` 和 DH 实时 `dhDepthTex0` 的最近不透明表面限制积分长度；不读取透明阶段才生成的 DH 深度副本。透射率按指数消光累积，云体照明分别计算日月方向五点透射与向上三点天空遮蔽，方向散射函数控制向光亮部，缓慢衰减的间接光近似保留厚云内部层次；这些项属于美术散射近似，不是完整多次散射求解。每个像素的每一段使用独立整数散列抖动，不进行时域积累；远处平滑淡出。阴雨云层在云距离的 25% 至 80% 区间，逐渐向同一视线的 `skyBackground` 底色融合，使厚云在距离裁剪前与天空衔接。该融合只作用于云内散射颜色，不改变地形深度限制、云的透射率或近处乌云的照明；水下使用共享的介质天空渐变。三档以 16/32/48 步为基础，长视线依据云体尺度与厚度增加分段，目标步长为 `16 × CLOUD_SCALE` 格与厚度的十六分之一中的较小值，最小 4 格，最多为基础步数的六倍。密云内透射率足够低时提前结束积分；地平线附近的开销须在游戏内测量。

主世界 `program/cloud_pass.fsh` 以半宽、半高分辨率计算散射与透射率，分别写入 `colortex1` RGBA16F 和 `colortex2` R32F 距离附件；两者尺寸相同，不与全分辨率附件混写。三档保留各自的积分步数，共享半分辨率与边缘补算策略。距离附件保存截断视线的普通/DH 最近有效不透明表面距离；散射保存相对同视线天空的差值，以便完整分辨率合成时维持地平线底色连续。1920×1080 下两份附件合计约 5.93 MiB，加载器双缓冲约 11.87 MiB；不增加发布贴图。目标 Oculus 1.8.0 的相对尺寸解析与 R32F 格式枚举已通过本地代码核对。

`lib/cloud_reconstruct.glsl` 先用原始分辨率深度排除云前地形，再按双线性空间权重与视线距离相近程度重建云层。遮挡边界缺少有效邻居或薄云轮廓变化快时平滑补充完整分辨率积分，保留细前景与天空缝隙；不使用时域历史或每帧随机抖动。`program/deferred.fsh` 在主世界 `deferred1` 合成完整分辨率场景和反射快照；地狱与末地仍在 `deferred` 复制场景。细小云形仍受缩小采样影响，复杂遮挡会增加补算成本；离线运动检查不能替代游戏内旋转视角和加载器验收。

“闪电照云”使用加载器提供的 `lightningBoltPosition`：前三个分量为相机相对位置，第四分量表示存在闪电实体。目标 Oculus 1.8.0 的输入注册、坐标转换、四维分量访问和 `IS_IRIS` 宏已通过本地代码核对。配置在该宏下使用两种响应速度的平滑值之差生成短脉冲；没有该接口或脉冲输入时亮光为零。效果仅在雷暴权重足够高时启用，普通雨天及其他维度保持原照明。

发光中心放在落雷柱上方的云体内，冷白光随水平与垂直距离衰减，并由现有密度和透射积分保留云体层次及前景遮挡；远处仍遵循同一大气颜色融合。半分辨率积分和完整分辨率补算使用相同输入，反射快照自然包含云内亮光。效果不新增纹理、缓冲或采样步数。输入只表示一个可见闪电实体的位置和存在状态，不包含分叉闪烁的精确时序；多道同时落雷、实体切换及客户端时间更新需要游戏内验收。

`python tools/test_cloud_lightning.py` 检查脉冲强度、无输入、开关、雷暴限定、局部衰减、普通/DH 前景、维度及透射率一致性；`.artifacts/validation/cloud-lightning-preview.png` 从左至右为无亮光、强亮光和弱亮光。预览经过显示映射，人工注入的脉冲不代表加载器内的事件时序验证。`python tools/benchmark_clouds.py --compare-lightning` 比较关闭、待机和亮起时的云积分与合成开销，结果写入 `.artifacts/validation/cloud-lightning-benchmark.json`。

云影准备阶段 `prepare1` 每帧写入独立的 256×256 `colortex7` RGBA16F 附件，几何阶段只读取当帧内容；不与全分辨率颜色附件混写。固定尺寸由 `size.buffer.colortex7` 指定，已核对本地 Oculus 1.8.0 的配置解析、准备阶段顺序及附件翻转路径。单份纹理约占 0.5 MiB，加载器双缓冲约占 1 MiB，不增加发布贴图。云底投影平面覆盖 `2048 × CLOUD_SCALE` 格，中心随相机投影位置按八格乘云尺度对齐；表面沿光线投到该平面后，全亮或全暗区域使用四点双线性读取，普通边缘使用十六点三次重建并限制透射率范围。十六点邻域的透射率极差在 0.55 至 0.90 之间平滑接入直接积分，保留强变化区域的细节；缓存边缘、云内或缓存外仍平滑交接或直接使用原积分；云上表面不受投影影响。月亮自定义纹理占用的 `gaux1` 与云影附件相互独立。

地面云影沿日月方向对相同密度场做最多十六点积分，仅乘到直射光上；雨天地面投影的光学深度超过 9 时停止，透射率余量小于 0.000124。云内天空遮蔽沿竖直方向积分至云顶，日月透射只采样有限邻域：长度不超过云厚与 `384 × CLOUD_SCALE` 格中的较大值，遇到云顶则提前截断；忽略邻域外的远云遮光。光源高度方向分量在 0 至 0.04 之间平滑减弱方向遮蔽与散射各向异性，使日月方向交接连续。普通和 DH 表面共享该计算，不依赖 DH 日月阴影图。投影是低采样近似，不模拟云影半影或多重散射；云内照明也不模拟地形向云投影。云影计算不改动原有方向光过滤。

移动使用 3600 秒闭合风场，与加载器计时器周期衔接；速度选项控制风场幅度。重载计时器会重置云的位置。没有云对透明物的精确交叉排序、多层天气、时域重建。雷暴权重由目标 Oculus 版本的 `thunderStrength` 提供；未上传该接口的加载器使用零权重，仍保留降雨响应。

`tools/test_clouds.py` 对实际 deferred 入口验证天气与群系覆盖差异、普通及 DH 前景深度、局部遮挡、云上云内观察、维度和介质隔离、开关和风场回绕。地面最多十六点云影与 128 点参考积分对比，并通过实际表面照明函数检查直射光减弱、环境光和方块光保留。`.artifacts/validation/clouds-preview.png` 从左至右为晴天、降雨、雷暴、高原晴天。`.artifacts/validation/cloud-weather-preview.png` 每行对应一个观察位置，三列分别为晴天、降雨、雷暴；高仰角检查覆盖率、云幕不透明度和云色暗度。预览不包含游戏地形或加载器运行时输入。

`tools/test_cloud_receivers.py` 在普通地形与 DH 地形的实际片元入口绘制相同世界空间平面，检查两条路径接收到相同云影、高原稀疏云仍能产生明暗对比、风场推动投影移动，以及云层上方的地形不受云影影响。云影跳过没有有效直射光的表面。它不替代游戏内 DH 顶点变换和输入上传的验证。

云层低仰角回归将默认积分与 256 步参考进行图像误差比较，覆盖接近地平线和斜向上视角。`.artifacts/validation/cloud-sampling-preview.png` 每行左侧为默认采样，右侧为参考采样；静态抖动仍可产生细颗粒噪点，不表示具备时域降噪能力。

`tools/test_cloud_horizon.py` 检查阴雨厚云与天空的远距离色彩衔接，覆盖四档云距离、普通及 DH 前景遮挡、水下天空，并输出 `.artifacts/validation/cloud-horizon-preview.png`；图中从左至右为 2000、4000、6000、8000 格云距离。

`tools/test_cloud_sunset.py` 冻结风场并小幅转动日月方向，检查两处观察位置、三种天气下的掠射光阴影与日月交接连续性。`.artifacts/validation/cloud-sunset-preview.png` 每行左、右为相邻光照方向，不包含游戏内时间与输入上传的验证。

`python tools/test_cloud_resolution.py` 将两阶段输出与相同积分参数的原分辨率结果对比，覆盖天气、云内视角、普通/DH 单像素前景、天空细缝、运动与奇数尺寸。`.artifacts/validation/cloud-resolution-preview.png` 每行从左至右为原分辨率、两阶段合成、放大五倍的绝对误差。`python tools/benchmark_clouds.py --compare-resolution --size 1024` 计入云积分与合成的全部绘制，输出 `.artifacts/validation/cloud-resolution-benchmark.json`；计时渲染器和功耗边界见报告。

`tools/test_cloud_noise.py` 检查生成资源一致性、GPU 插值、负坐标和周期接缝。`tools/test_clouds.py` 对晴天、雨天与雷暴的低仰角视线分别比较高采样参考。`python tools/benchmark_clouds.py` 记录默认云质量在固定人工场景中的晴雨云绘制与云影 GPU 时间，支持 `--samples 16`、`--samples 48` 和 `--size`；结果写入 `.artifacts/validation/cloud-benchmark.json`。计时只包围绘制调用，不计编译、纹理上传和读回，不代表游戏整帧性能。

## 水深与群系水色

`python tools/benchmark_clouds.py --diagnose` 分别计时完整云、仅保留密度积分、关闭云、地面云影及关闭云影，结果写入 `.artifacts/validation/cloud-diagnosis.json`。仅密度模式在离线编译输入中替换照明表达式，不修改发布资源。`python tools/benchmark_water.py` 使用实际水面和表面光照函数，在固定透视深水场景中逐项关闭云影、反射、泡沫、折射或波纹，并分别测量启用与禁用 DH 深度路径的绘制；结果写入 `.artifacts/validation/water-benchmark.json`。测试不包含地形阴影图、游戏几何、区块调度或多层透明覆盖，也不代表含岸壁或水下视角的开销。

`python tools/test_cloud_shadow_map.py` 对比缓存与相同采样数的直接积分，检查相机移动时世界投影稳定、缓存边界、云内与云上表面、低角度光线和天气风场更新。`python tools/benchmark_cloud_shadow_map.py` 测量固定地表人工场景中云影附件生成与接收的总 GPU 时间，覆盖两处位置与晴天、降雨、雷暴，输出 `.artifacts/validation/cloud-shadow-map-benchmark.json`；可用 `--size` 调整正方形渲染尺寸。该测试不代表游戏整帧耗时。`python tools/benchmark_water.py --compare-cache` 在同一进程、相同场景中比较直接积分与缓存，缓存结果包含准备阶段和水面绘制的 GPU 耗时。

计时使用 GPU 查询，累计单次场景提交中的所有绘制调用；记录渲染器、分辨率和原始计时样本，功耗状态未控制。关闭单项可能改变编译器优化和执行分支，各项差值不能相加。游戏内归因需在同一位置、视角、时间、天气、预设、分辨率和视距条件下逐项关闭选项，并比较帧时间；不同视角的帧率差不能全部归给某个效果。

`lib/water_surface.glsl` 在透明阶段读取普通不透明深度 `depthtex1` 与 DH 不透明副本 `dhDepthTex1`，分别用对应投影逆矩阵还原位置，近景优先使用水面后方的普通有效表面，缺失时由 DH 补位，交接范围外选择较近表面。顶面取该表面与水面的垂直高度差作为可见水深，侧面取穿水路径长度；两者平滑混合。该深度是屏幕空间估计，斜坡、交叠水层与屏幕外地形不能视为完整水体体积。无有效水底时采用 24 格的深水近似。

两格以内吸收部分保留 1.5% 的轻微表面覆盖；水外视角另按菲涅耳比例合成反射，深水通过连续的指数吸收逐渐增加颜色与遮挡。`WATER_OPACITY` 保留选项标识与数值，控制深水吸收。海洋色调为蓝，河流色调为绿，其余为中性；群系自定义 uniform 根据玩家所在群系平滑过渡，不具备远处逐片水域的独立分类。普通水只处理水材质编号，DH 水只处理加载器水材质标识，其他透明材质保留原路径。

水下雾在最终阶段根据普通和 DH 的最近完整深度累计吸收，透明水面可以终止穿水距离，`WATER_FOG_DENSITY` 控制强度；这不是相机距水面的垂直深度。水面外的空气段不计入水雾；复杂多层透明介质及未绘制的水面边界没有完整体积追踪。水下向下观察的远处背景采用深水颜色，向上观察保留天空渐变；无实体遮挡的水面背面使用天空快照并按相机到水面的距离施加水雾。水面提供屏幕空间折射，不提供几何波浪。

`tools/test_water.py` 检查浅水阈值、深水单调吸收、群系色调、普通/DH 不同投影的水深一致性、近景水底优先、缺失深度和透明材质隔离。实际加载器输入、远景水深和游戏画面需要游戏验收。

## 水面波纹与浅水浪花

`lib/water_waves.glsl` 在世界空间叠加三个尺度的随机波面解析梯度，以扰动法线形成细碎日月高光；不改变顶点位置和水深。五次插值保持单元边界的斜率连续，旋转采样方向与不同速度的平移打散规则排列。大尺度起伏较弱，中尺度承担主要波纹，细尺度随距离优先衰减；无额外纹理读取。平移沿闭合轨迹运动，配置提供的各档速度均在 3600 秒时钟回绕处连续。远处采用距离衰减，未实现逐像素波纹频谱积分，极低视角的细节稳定性仍需游戏内验收。高光与浪花在线性预乘颜色中组合，再换算成普通透明混合所需的输出，避免浅水透明度吞掉亮部。

白色浪花根据浅水深度等值线形成流动波带，并以空间纹理打散覆盖。仅作用于水面顶面及水外视角，缺失水底时不生成浪花；侧壁、水下和非水透明材质不参与。八方向邻域重建实体位置，仅接受贴近水面的岸壁并按横向距离淡出；平坦浅滩不产生泡沫。屏幕外岸壁无法参与检测，不模拟水动力破浪。细节随距离衰减，普通与 DH 使用同一算法。

`tools/test_water.py` 验证波动随时间变化、浅水吸收保留、浪花强度与断续覆盖、深水和水下隔离、普通与 DH 的一致性以及时钟回绕。`.artifacts/validation/water-waves-preview.png` 以棋盘水底对照 0.25、0.75、2、8 格水深。离线预览不替代游戏内光照角度与岸线验收。

`python tools/test_water_ripples.py` 验证波纹频谱分散、单位法线、距离衰减、开关与所有配置速度的时钟连续性，输出 `.artifacts/validation/water-ripples-preview.png`；从左到右分别为近处初始、近处两秒后和远处的人工反光图。

## 水面反射

`lib/water_reflections.glsl` 使用云合成阶段双输出保存的 `colortex5`，避免在透明阶段读取正在写入的场景颜色，也避开几何阶段的材质与光照纹理槽位。快照包含体积云，不包含透明物。参考接口：[Iris 颜色附件](https://shaders.properties/current/reference/buffers/colortex/)。

水面世界空间反射方向沿 16 个递增距离采样，在深度交叉处进行 5 次细分；普通与 DH 深度分别重建，近景优先使用普通有效实体，远景选择较近实体。仅接受水面以上的命中，避免把水底当成倒影。屏幕边缘淡出，缺失景物用受天空暴露程度限制的天空渐变补足；天空颜色快照仅在采样位置无实体遮挡时使用。无法重建屏幕外景物、透明物或准确的离屏云层。

菲涅耳反射与深水吸收按能量比例组合，保留俯视浅水的清澈；中性水仅保留低亮度散射。波面法线同时影响倒影与日月高光。额外开销包括全分辨率半浮点快照、反射射线及浅岸邻域查询；实际帧时间待游戏测量，可独立关闭水面反射。

`tools/test_water_reflections.py` 检查实际双附件快照、透视岸壁命中、波面倒影移动和普通/DH 一致性，输出 `.artifacts/validation/water-reflection-preview.png`。这是人工场景的 GPU 验证，不能代替游戏内水色、岸线及视角变化验收。

## 普通水与远景水交接

`water_handoff.glsl` 以水平距离组织交接。存在普通不透明地形的像素在 `max(16, far-64)` 格内排除 DH 水；没有普通地形的像素保留 DH 水补位。DH 水在 `colortex6` 记录视深、水面高度、法线朝向和有效标记，附件单独关闭混合，每帧清零。普通水只读取此附件，不写入它；DH 水只写入，不采样正在绘制的附件。

普通水检测到高度差小于 0.35 格、朝上的 DH 水面标记时跳过重复绘制。非水材质、侧壁及明显不同高度的水体保持原路径。标记采用最近像素读取，避免边缘插值生成不存在的覆盖。这是顶面交接，不是通用透明物排序；小于高度容差的独立水层及特殊水面几何仍需实景检查。

`test_water.py` 以 DH 水先绘制、普通水后绘制的双附件与真实透明混合，覆盖多个交接距离和边界小步移动，对比单层水的颜色与透明度，同时检查近景排除、缺失地形补位、材质和高度隔离。人工场景不能验证区块加载延迟或全部 DH 简化误差。

## 流水方向与折射

顶面几何导数提供坡面法线，重力投影到切平面后决定波纹运动方向；近水平水面保留多方向涟漪，陡坡与垂直面使用顺流和横向细纹。水幕白沫是低覆盖率的程序细条，不代表真实撞击飞沫或落点检测。水面网格及流体传播保持原版规则。

水面法线差投影为小幅屏幕偏移，读取不透明快照的颜色差，以剩余透射率叠加到透明混合结果。采样必须位于屏幕内和水面后方，顶面还要求采样实体低于水面；拒绝不满足条件的偏移。该方法保留现有透明合成，但不是复杂多层透明介质的精确折射。

`test_water_flow.py` 验证坡面及两种朝向水幕的顺流移动、计时回绕与白沫覆盖；`test_water_reflections.py` 验证水后图案折射和水外画面隔离。实际流水边界与视觉观感需要游戏验收。

## 水下视野与地形焦散

几何阶段在水下保留未施加水雾的颜色，最终阶段读取含透明水面的 `depthtex0` 与 `dhDepthTex0`，分别重建距离，按较近的有效表面累计水雾。穿水距离至出水界面结束，山体和云不按其完整距离进行水雾吸收。缺失有效深度时保留背景。体积云在水下仍按天空视线绘制，并使用天空色处理远处衰减；熔岩和细雪中关闭。

水底焦散作用于水下视角的近处普通地形，限于位于相机下方且朝上的表面。同一套水面波纹法线决定阳光折射方向，通过相邻光线落点的面积变化估计聚光，仅增强直射光，因此受天空暴露、太阳高度、阴影及云影控制，不增加环境光和手持光源。效果随距离淡出，可独立关闭或调整强度。入射面近似为相机上方一格的局部平面，不获取真实逐点水位，不作用于 DH 远景，也不承诺透过复杂玻璃观察干燥地形时的水体分类完全准确。

`test_underwater_view.py` 检查短穿水距离不会压黑景物、持续长水路吸收、普通与 DH 的距离一致性，以及焦散运动、水外/夜间/无天空光隔离，输出离线焦散预览。游戏内观感与性能需要实测。

水下水面背面使用翻转的同一波面法线，透射颜色来自不透明及天空快照，以波纹扰动采样；反射追踪水面下方可见实体，离屏部分以受天空光影响的水色近似。反射权重随视角从 0.02 平滑增加至 0.65，保持斜视时水上景物的可读性。这是美术近似，不模拟真实临界角及完全内反射，不重建屏幕外景物，也不是完整的折射视角重渲染。`test_water.py` 用斜视区域的彩色背景验证透射轮廓与普通/DH 一致性。

焦散没有独立的随机多边形纹理；波面关闭或强度归零时没有聚光，波动速度为零时焦散同步静止。`test_underwater_view.py` 验证这些关联，`test_water.py` 验证水面背面正视透射、斜视反射及波纹运动。离线预览只验证人工场景，不代表游戏内效果验收。

## 水下阳光散射

`lib/underwater_light.glsl` 沿水下视线积分阳光散射，距离由最近普通/DH 完整深度限制，最多 40 格；水面与前景会终止积分。每段使用一次硬件阴影比较，岸壁和树木等阴影投射物控制可见光束。超出有效阴影覆盖时淡出，不将未知区域视为受光；仅主世界水中、太阳位于地平线上方且开启阴影时生效，降雨使其淡出。未渲染到阴影图的遮挡物无法参与，DH 地形仅限制视线路径，不投射此光束的阴影。

散射与遮挡使用同一太阳方向；归一化的 Henyey–Greenstein 相函数采用 0.72 的前向系数，朝向太阳时直接散射较强，背向太阳时较弱。光束明暗由阴影投射物决定，无遮挡的均匀水体只产生平滑散射。沿世界距离固定的短积分段在中点采样遮挡，最后一段由水面或前景截断，并解析积分分通道透射率。不添加像素随机偏移或空间噪声光柱。射线原点取逆视图矩阵的平移分量，与表面几何的世界坐标重建一致；投影原点与方向在循环外计算，透射率按段递推。颜色随太阳高度改变冷暖。云的局部投影未参与光束积分，天气负责整体减弱；不模拟水面折射、多次散射和准确的入水深度吸收。有限步距在细小遮挡或低质量下仍可能残留离散误差；没有历史帧累积。

`program/underwater_pass.fsh` 在 `composite` 阶段复用半宽半高的 `colortex1` RGBA16F：RGB 保存散射，A 保存截断至 40 格的积分长度。该附件的云数据已在 `deferred1` 消费，不再供透明阶段读取；没有额外发布贴图或颜色附件。`final` 依据完整深度进行四点重建，没有匹配深度时按当前像素补算，防止细小前景漏光。水雾先作用于场景颜色，再叠加已按距离衰减的散射，不重复吸收光束。没有有效完整深度时不生成光束。

“水下阳光光束”提供开关、强度与质量；土豆预设关闭光束，默认与极致开启；三档保存的质量值分别为 4、8、12，对应 1、0.5、约 0.333 格的积分步距；40 格路径最多分别采样 40、80、120 次，短路径提前结束。`python tools/test_underwater_light.py` 运行实际两阶段程序，验证太阳方向及背光抑制、镜头平移坐标一致性、地形遮挡、雨夜关闭、维度与介质隔离、普通/DH 一致性、单像素前景、均匀介质积分平滑性、孤立遮挡轮廓及倾斜水底与 1/32 格步距参考对比、遮挡区域局部误差与高频误差检查及完整分辨率对照，输出 `.artifacts/validation/underwater-light-preview.png`。加 `--benchmark` 记录两阶段 GPU 总耗时至 `.artifacts/validation/underwater-light-benchmark.json`，人工场景不代表游戏内帧率，画面与性能仍须在目标加载器验收。


## 植被顶点动画

`lib/vegetation_wind.glsl` 使用相机相对世界坐标、`cameraPosition` 和客户端时钟构造共用风场。普通地形的 `surface.vsh` 与 `shadow.vsh` 在投影前施加同一位移，分别用 `gbufferModelView` 与 `shadowModelView` 转回对应视图空间。实体、手部、透明水面、DH、下界与末地不应用此动画。阴影仍按植物纹理透明度裁剪。

`block.properties` 的 10101–10110 对应草与花、作物、双格陆生植物下半与上半、甘蔗、单格海草、双格海草下半与上半、海带、树叶。白名单不包含南瓜、西瓜或其他完整作物方块。`at_midBlock` 按 1/64 方块解码为方块中心偏移；本机 Oculus 1.8.0 的顶点格式和填充函数已核对该语义。草与作物使用顶点离底部的归一化高度平方衰减，双格植物共用下半方块的中心和两格高度，连接处相位与位移一致。模型本身的偏移、资源包几何与加载器改写仍需游戏内验收。

甘蔗和海带没有整株根部、高度接口，使用小幅连续世界坐标位移；各段不会由于独立相位而裂开，但根部并非严格固定。树叶同样按实际顶点坐标求值，相邻叶块的共用顶点获得相同位移。顶点运动只改变 XZ，不改变 Y；保留输入法线，以小摆幅近似表面朝向，不模拟弹性枝条或植物碰撞。

风场叠加主方向摆动、横向细摆与缓慢阵风，陆生植物随降雨和雷暴增强，水生植物速度较低且不受天气增强影响。速度档位在 3600 秒的时钟回绕处相位闭合，空间周期为 512 格。距离依据相机相对坐标在 64–160 格之间平滑淡出。三档默认开启，未添加额外纹理、片元采样、历史帧或渲染附件；费用随可见和投影的植物顶点数量变化。

`python tools/test_vegetation_wind.py` 用变换反馈捕获实际地形与阴影顶点入口，验证根部、双格接缝、相邻叶块与连续茎段、镜头移动、不同视图矩阵的阴影同步、天气响应、速度回绕、开关及维度和几何隔离。加 `--benchmark` 对相同数量的顶点比较开关两种路径，记录 GPU 与耗时至 `.artifacts/validation/vegetation-wind-benchmark.json`；计时含变换反馈写回但不含片元、阴影图光栅化或完整游戏开销，不能作为游戏帧率承诺。


## 船舱挡水深度

Oculus 1.8.0 的船舱挡水遮罩使用实体程序及关闭透明裁剪的状态，只写深度，不写颜色。`surface.fsh` 的实体路径遵循 `alphaTestRef`，阈值为 0 时保留零透明度片元，使游戏提供的遮罩可以阻挡后续水面；阈值大于 0 时仍裁剪透明纹理。材质颜色不用于推断船型，也不对所有实体周围的水挖洞。此行为依赖加载器提交遮罩几何和正确的深度、颜色写入状态；模组船若没有提供挡水遮罩，不在此保证范围内。

`python tools/test_boat_water_mask.py` 编译各维度实体入口及 DH 宏组合，在人工场景中验证只写深度的遮罩保留船舱颜色、阻挡后续水面且不影响外侧水域，并检查普通透明裁剪。测试包含强制裁剪零透明度片元的故障对照。实际船模、乘船视角和加载器改写需在游戏内验收。
